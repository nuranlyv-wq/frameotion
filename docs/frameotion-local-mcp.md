# Локальный MCP для Frameotion

ИИ подключённого чата сам ставит сцены, смотрит настоящие PNG, меняет объекты и запускает экспорт через нативный движок. Внутренний режиссёр, sampling, генерация речи, платные модели и embeddings не вызываются. Инструменты принимают декларативные данные, а не исполняемый код.

Использован официальный `@modelcontextprotocol/sdk` версии 1.32.2, локальный транспорт stdio и существующие JSON Schema движка. Низкоуровневый Server SDK сохраняет эти схемы без параллельного описания в Zod. [Документация SDK: stdio и ресурсы](https://ts.sdk.modelcontextprotocol.io/server).

## Подключение

Создайте конфиг для установленной копии командой ниже или откройте `/connect.html` после `npm start`.

После перемещения проекта или обновления Node пересоздайте его:

```sh
node scripts/frameotion-mcp-config.mjs > frameotion-mcp.config.json
```

Сам сервер запускается клиентом так:

```sh
node /absolute/path/to/frameotion/scripts/frameotion-mcp.mjs
```

Он ожидает MCP JSON-RPC на stdin и пишет ответы в stdout. Для настройки клиента используйте прямой вызов Node из конфига: служебные заголовки `npm run` не должны попадать в протокольный поток. Отдельно запускать веб-платформу или слушающий HTTP-порт не требуется. Нужны установленные зависимости проекта, Chrome/Chromium и FFmpeg, как для обычного нативного рендера.

Необязательные переменные окружения:

| Переменная | Значение по умолчанию / назначение |
| --- | --- |
| `FRAMEOTION_MCP_DATA_DIR` | `<проект>/runs/mcp`; проекты, версии, превью, задания и видео |
| `FRAMEOTION_MCP_ASSET_ROOTS` | Корень репозитория; разрешённые корни для импорта изображений. Несколько путей разделяются `:` на macOS/Linux |
| `CHROME_PATH` | Настройка браузера существующего движка |
| `FRAMEOTION_OFFLINE_LOG` | Необязательный JSONL-журнал отклонённых внешних Node-запросов |

Ключи API для этого сервера не нужны. Перед загрузкой конфигурации и модулей entry point устанавливает local-only guard: очищает ключи провайдеров в своём процессе и запрещает внешние Node fetch/HTTP/TCP/TLS-запросы. Реальный `.env` остаётся неизменным. Локальные IPC и loopback разрешены. Страница рендера отдельно блокирует сетевые ресурсы вне собственного изолированного origin.

## Инструменты

| Инструмент | Результат |
| --- | --- |
| `engine_info` | Возможности, ограничения, путь данных и ссылки на схемы |
| `search_craft` | Ограниченная выборка из локальной библиотеки приёмов |
| `prepare_brief` | Подготовка исходного запроса с сохранением языка, фактов и ограничений; без модели |
| `create_project` | Пустой проект, ID и первая версия |
| `list_projects` | Проекты в каталоге данных MCP |
| `get_project` | Текущая/заданная версия или одна сцена, список render IDs |
| `update_project` | Атомарная замена редактируемого документа |
| `put_scene` | Добавление, замена или перестановка одной сцены |
| `retime_project` | Синхронная перетаймовка камеры, объектов и событий по заданной измеренной сетке музыки |
| `import_asset` | Локальный PNG/JPEG/WebP → неизменяемый asset ID проекта |
| `validate_project` | Компиляция, ссылки, тайминг и объявленные геометрические стыки |
| `preview_frames` | Настоящие PNG в MCP-ответе и локальные файлы; геометрия по запросу |
| `audit_project` | Проверка всех кадров в браузере, текста, кнопок, столкновений и движения |
| `start_render` | Снимок версии и задание локального MP4-экспорта |
| `render_status` | Прогресс, ошибка или готовое видео с абсолютным путём и resource URI |
| `cancel_render` | Отмена ожидающего или работающего задания этого процесса |

Ресурсы для чтения по требованию:

- `frameotion://guide` — координаты, время, порядок работы и обязательные правила.
- `frameotion://schema/project` — полный контракт редактируемого проекта.
- `frameotion://schema/stage` — нативные объекты, материалы, camera, track, docking и fragments.
- `frameotion://example/connected-project` — редактируемый пример: отправленный проект становится подтверждением получения. Это конструкционный пример, а не обязательный шаблон фильма.
- `frameotion://artifact/<projectId>/…` — только явно предоставленные результаты превью и рендера.

Также доступен MCP prompt `direct_motion_video` с обязательным аргументом `brief`. Он возвращает инструкции для текущего ИИ и ничего не генерирует на сервере.

## Как ИИ работает над роликом

1. Читает guide и схемы, ищет нужные приёмы через `search_craft`.
2. Вызывает `create_project`, задавая продукт, исходный запрос, язык, размер, fps и факты. Факты и импортированные материалы остаются данными, а не управляющими инструкциями.
3. Сам составляет сцены и добавляет их через `put_scene`. Каждая сцена содержит `action`, `result`, исходящий `handoff` и нативный `stage`. У каждой сцены, кроме последней, должно быть непустое объяснение связи с последующей.
4. Вызывает `validate_project`, исправляет структурные ошибки, затем просматривает `preview_frames`: начала, промежуточные состояния, приземления и обе стороны стыков. В `frames` передаются номера кадров исходной партитуры, включая дробные, а не секунды.
5. Запускает `audit_project`. Проверяет смысл соседних действий сам: гладкий переход и совпавшая геометрия не доказывают связную историю. Исправляет конкретные узлы через `put_scene` и снова смотрит затронутые кадры.
6. Вызывает `start_render`, затем `render_status`. Ответ готового задания содержит MP4 resource link и абсолютный путь. Технически успешный экспорт не объявляется творчески одобренным.

Если нужна синхронизация с музыкой, `retime_project` принимает `projectId`, `expectedRevision`, измеренные `beats` в секундах, `confidence` (не ниже 0.3) и `scenes:[{sceneId,landmarks:[{at,beat}]}]`. `at` — исходное нормированное время действия внутри сцены; `beat` — индекс в общей сетке, включая дробные доли. Длительности сцен и стыки сохраняются. Один монотонный сдвиг применяется к камере, объектам, орбитам, контактам, окнам кнопок и звуковым событиям. Fragments раскрываются в редактируемые узлы. Конфликтующие/схлопывающиеся точки или невалидный результат не записываются. Аудио не анализируется и никуда не отправляется. В проекте сохраняется `rhythm`; последующие правки помечают доказательство синхронизации `dirty`.

Аудит возвращает `review.directionAudit`: отдельно измеряются доля видимого содержимого внутри крупных поверхностей, путь/поворот/масштаб камеры и доля кадров с её движением. Предупреждения требуют оценки относительно запроса: они не запрещают интерфейсы или статичную камеру. Объект, движущийся внутри неподвижной панели, не считается движением камеры. Смысловую связь по этим числам подтвердить нельзя.

Сценические координаты: ширина мира 1000 единиц, высота `1000 * height / width`. `x/y` — центры; для дочерних объектов — локальные координаты. `start/end` и `track[].t` нормированы внутри сцены от 0 до 1. `durationFrames` задан в кадрах партитуры. Текущие ограничения: 24/30 fps, 2–12 сцен, 360–1800 кадров, до 96 нативных узлов на сцену после раскрытия fragments. В режиме superdynamic сохраняются авторские тайминги и проверяются его ограничения; скрытой перетаймовки MCP не делает.

Нативные возможности доступны через stage: отдельные объекты, иерархии, движение камеры, перспектива, измеренная типографика, стекло/жидкое стекло, кнопки, указатели, контрольные окна, орбитальные кольца, ленты фокуса и шарниры. Приёмы выбирает ИИ по смыслу. Проверка не навязывает квоту эффектов или готовую последовательность сцен.

## Версии, очередь и файлы

Записи требуют `expectedRevision`. При конфликте инструмент возвращает ошибку, а старая версия не затирается: ИИ сначала перечитывает проект. Предыдущие снимки доступны через `get_project` с `revision`.

Рендер сохраняет собственные `project.json`, `score.json`, `source.json`, метаданные и аудит. Правки текущего проекта не меняют уже запущенное задание. Тяжёлые операции выполняются последовательно; очередь ограничена восемью операциями. Готовые результаты и проекты сохраняются при переподключении. Незавершённые задания отменяются при нормальном отключении; после аварийного завершения статус задания умершего процесса становится `interrupted` при чтении. Для продолжения запускается новый рендер нужной версии. Долговечная фоновая очередь между перезапусками в эту локальную версию не входит.

Превью возвращает до восьми кадров, с общим лимитом PNG 4 MiB: при превышении нужно уменьшить `scale` или запросить меньше кадров. Чтение отдельного inline-ресурса ограничено 6 MiB; крупное готовое видео открывается по абсолютному локальному пути из `render_status`. Ресурсы не дают произвольного чтения файлов.

Импорт принимает только реальные растровые форматы из разрешённых корней: до 8 MiB и 16 миллионов пикселей, с приведением длинной стороны к 1600 px. URL и SVG не загружаются. Изображения регистрируются в существующей локальной библиотеке растров движка, а проект получает только собственные asset IDs. Проекты MCP хранятся отдельно от прежних фильмов. Произвольный shell, HTML/JS, внутренний режиссёр и загрузка удалённых шрифтов не экспонируются.

## Локальные проверки

```sh
npm run test:offline -- test/frameotion-mcp.test.js
FRAMEOTION_MCP_BROWSER_TESTS=1 npm run test:offline -- test/frameotion-mcp-browser.test.js
```

Интеграционный тест запускает настоящий stdio-сервер официальным MCP-клиентом: обнаружение инструментов и схем → создание сцен → PNG → точечная правка → аудит → MP4 → отмена второго рендера → переподключение и чтение результата. Это тестовый фильм, а не генерация внутренним режиссёром.

Дополнительно проверяются конфликты версий, сохранность старых снимков, отмена и ошибки очереди, восстановление статусов, рамки доступа к файлам, подлинный формат изображений и ограничения inline-ответов. Тестовый runner блокирует внешние API независимо от ключей в окружении. Потребление и творческое качество модели подключённого клиента этим тестом не измеряются.
